# 現状とこれからの対応

2026-10-22 時点。数字は記録単位で分けた交差検証（学習に使っていない記録で評価）。

## 現状

### 打鍵の判定

| 判定 | 中身 | 単語（続けて打つ）の打鍵での誤り（取りこぼしを含む） |
|---|---|---|
| 押してずらす | 高さのしきい値で押す・離すを区切り、触れている間のずれで方向を決める | — |
| スライド | 触れ始めのキー、滑らせた向き、押し直しの分割、フリックは 0.7 キー以上 | 25.6%（ルール） |
| 学習 | 候補の切り出し + LightGBM（打鍵ではない／単押し／フリック）+ 方向は軌跡の向き | 13.6% |

- 学習データ：データ収集（1 打鍵）5 回・（単語）7 回、候補 814 個。キーボードはすべて右手のひら（左手で入力）
- 実機（練習のフレーズ入力）で誤りを数えると、主な原因は「単押しのあと、指を上げずに次のキーへ滑る動きをフリックにしてしまう」ことだった。これは距離による上書き（1.2 キー以上は必ずフリック）を外して、モデルに任せることで減らした（このモデルの実機での確認はまだ）
- キーのずれ（触れ始めたキーが目標と違う）が約 1 割ある。決まった向きへの偏りではなく、ばらつき（標準偏差 約 0.45 キー）なので、位置の補正では減らない

### 道具

- 記録：自動調整・練習・データ収集のたびに `files/sessions/<開始時刻>/` に `frames.csv`・`joints.csv`・`trials.csv`・`prompts.csv`
- 再生：`ReplayTest`（判定どうしをフレーズ入力の記録で比べる。記録したときの判定に有利）
- 学習：`ml/`（候補の書き出し → 正解付け → 学習 → 端末用に書き出し）。手順は [ml/README.md](../ml/README.md)
- 実機の誤りの切り分け：`ml/diagnose.py`（練習の記録の誤りを、キー違い・種類違い・取りこぼし・余計な入力に分ける）

## これからの対応

優先度の高い順。

### 1. 学習の判定を実機で確かめる（すぐ）

- 上書きを外したモデルで練習を何回か打ち、`ml/diagnose.py` で前回（正しい 76.5%、種類違い 11.8%、キー違い 9.8%）と比べる
- 比べるときは、キーボードの設定（大きさ・位置・奥行き・接触しきい値）を同じにする

### 2. 余計な入力（暴発）を減らす

- フレーズの最初に、手をキーボードに持ってくる途中の浅い動きが候補になり、文字が入ることがある
- 候補の切り出しで除くか（例：速く近づいてくる途中の浅い候補は出さない）、特徴量で見分けられるようにするかを、記録で決める
- 「打鍵ではない」の正解率がまだ 3 割程度。正解の付け方（1 打鍵の時間枠の 2 つ目の候補を一律に「打鍵ではない」にしている）を見直す

### 3. 特徴量を増やす

- `joints.csv` はすでに記録している。指の第 1・第 2 関節の角度（指の腹で触れたか、先で触れたか）、キーボード側の手が押されて沈む動きを特徴量にして、効くかを確かめる
  - 端末でも同じ値を計算する必要があるので、関節を判定に渡す口（今は指先だけ）を足す
- 高さを接触しきい値からではなく、手のひらの表面（計測できる）から測る。設定に左右されにくくなる

### 4. データを増やす

- データ収集（単語）を続ける。単語の打鍵の誤りが下がり止まるまで
- 練習（フレーズ入力）の記録にも正解を付けて学習に使う。`diagnose.py` の対応づけをそのまま使える。訂正（⌫ と打ち直し）を除く処理が要る
- 姿勢や腕の角度などの自然なばらつきは入れる。キーボードの設定は当面固定

### 5. 言語モデル（キーのずれに効く）

- 今は打鍵ごとに 1 文字に決めている。キーの候補ごとの確率（位置のばらつきから）と、種類の確率（モデル）を残し、かなの n-gram 言語モデルと組み合わせて、文字列全体でもっともらしいものを選ぶ
- 判定の仕組みが大きく変わるので、判定（1〜3）が固まってから

### 6. そのほか

- **スライド判定にも「移動後の押し直し」を入れる**：記録の再生では、ルールでも単語の誤りが 36% → 26% に下がった
- **BO による自動調整の再開**：判定が固まってから。学習の判定が接触しきい値のずれを吸収するなら、探すのは大きさ・位置だけにできる
- **左手のひらへの対応**：多くの人に合うのはこちら。左手用のデータを別に取り、モデルを分ける
- **確定の遅れ**：今は指を離した時点で確定している。モデルの確信が高ければ、離す前に確定できる
- **記録の容量**：`joints.csv` は 2 分で約 6 MB。必要なら間引くか圧縮する
- **ブランチ**：作業は `ml-data-collection`（`calibration-and-slide-detection` から分岐）。main へのマージか PR は未対応
